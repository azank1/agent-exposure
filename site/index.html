    What it checks

    It replays your migrations in order, the way Postgres ran them, so a later enable row level security, rename, revoke, drop or DO loop counts. It flags tables in an exposed schema with row-level security off, default privileges that grant every new table to anon, views that skip row-level security because they lack security_invoker, and policies that let anyone, or any signed-in user, change or delete rows they don't own. Findings are graded by what the migrations grant.

    It reads migrations, not your live database. Supabase's Security Advisor checks a project's database; this checks the SQL before it gets there. Every grade was reproduced in Supabase's Postgres 17 image.

    Checks from agent-check , MIT licensed. It also flags risky AI-agent setup and CI agents that outside text can drive; those checks run in the GitHub Action.
